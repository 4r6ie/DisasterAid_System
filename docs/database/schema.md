## Tables

| Table | Purpose | Key columns |
| --- | --- | --- |
| `users` | Accounts and staff | `name`, `email`, `password`, `phone`, `address` |
| `disaster_incidents` | Recorded disasters | `incident_id`, `disaster_type`, `severity`, `status`, `latitude`, `longitude`, casualty counters |
| `emergency_reports` | Incoming emergency calls | `emergency_type`, `priority`, `status`, `people_needing_help` |
| `assistance_requests` | Relief requests | `request_number`, `assistance_type`, `urgency`, `status` |
| `evacuation_centers` | Shelters | `capacity`, `current_occupancy`, `status`, coordinates |
| `relief_items` | Stock catalogue | `category`, `quantity`, `min_stock`, `unit_cost`, `expiry_date` |
| `inventory_transactions` | Stock movements | `type`, `quantity`, `reference_type`, `transaction_date` |
| `responders` | Response personnel | `employee_id`, `specialization`, `status`, `rank` |
| `volunteers` | Volunteers | `name`, `email`, `skills`, `status` |
| `volunteer_assignments` | Volunteer deployments | `role`, `status`, `started_at`, `completed_at` |
| `affected_persons` | Affected individuals | `name`, `condition`, `evacuation_center_id` |
| `announcements` | Public advisories | `title`, `content`, `type`, `audience`, `is_published` |
| `audit_logs` | Activity trail (Spatie) | `description`, `subject_type`, `causer_id`, `properties` |
| `roles`, `permissions`, `model_has_roles`, `model_has_permissions`, `role_has_permissions` | Spatie permissions | — |
| `personal_access_tokens` | Sanctum tokens | `token`, `abilities`, `last_used_at` |
| `password_reset_tokens` | Password resets | `email`, `token`, `created_at` |

## Conventions

- All tables use an auto-incrementing `id`, `created_at` and `updated_at`.
- Soft deletes are used on operational records (`deleted_at`) so history is
  preserved; `audit_logs` is append-only.
- Enumerated values are stored as native `ENUM` columns in PostgreSQL and
  validated in the form requests.
- Coordinates are `decimal(10, 8)` / `decimal(11, 8)` and indexed for the
  nearby lookups, which use a haversine distance expression.
- Reference numbers (`DIS-YYYY-NNN`, `REQ-YYYY-NNNN`) are generated by the
  services and stored in unique columns.

## Seeders

`database/seeders/DatabaseSeeder.php` runs:

1. `RolesAndPermissionsSeeder` — the full permission catalogue and the five
   roles.
2. `AdminUserSeeder` — a `super_admin` account using `ADMIN_EMAIL` /
   `ADMIN_PASSWORD` (defaults `admin@disasteraid.test` / `password`).

## Migrations

```bash
cd backend
php artisan migrate --seed
```

To rebuild the database from scratch:

```bash
php artisan migrate:fresh --seed
```
